# Arbora MiniC CodeT5

## Intended use

Research and educational experiments on MiniC syntax repair and parser-AST linearization. Not intended for production code modification, general-purpose C, secure code generation, or semantic-preservation claims.

## Data

Training/evaluation data is generated by Arbora's seeded TypeScript grammar generator, corrupted by its seeded one-error injector, and checked by its deterministic parser. A separate OOD set contains Supabase samples and 20 handwritten examples when available. Generator bias, single-error corruption, and MiniC-only scope are substantial limitations.

## Training procedure

Two independent `Salesforce/codet5-small` Seq2Seq models are trained with config-driven Hugging Face Seq2SeqTrainer, seed 42, AdamW at `3e-4`, linear warmup/decay, 4 default epochs, per-epoch validation, exact-match best checkpoint selection, and early stopping. Repair decoding returns eight beams and deterministic parser verification is reported separately from exact correctness. AST output is not silently repaired.

## Results

No neural model metrics are claimed by this repository snapshot. Reproduce training and evaluation using `ml/README.md`; reports with bootstrap 95% confidence intervals and test-set sizes are written only by successful evaluation runs.

## Limitations

- Synthetic programs and grammar-aligned errors can favor the generator or repair oracle.
- The primary repair task assumes one injected syntax error.
- Parser validity does not imply syntactic intent, semantic correctness, or behavior preservation.
- Exact source match is formatting-sensitive; AST match is only structural under the parser's representation.
- MiniC is not full C; results do not generalize to arbitrary C projects.
