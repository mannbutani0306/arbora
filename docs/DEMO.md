# Three-minute Arbora demo

Use a local app and a known sample before presenting. Do not promise that an external model is warm.

## Before the demo

1. Start the frontend and open `/playground`.
2. If presenting Gemini or Arbora-T5, verify the Supabase gateway and selected provider are available. Never paste private keys into the browser.
3. Warm the optional model service using the checklist below.
4. If remote AI is unavailable, use the Classical engine and explain that it is a deterministic baseline, not a model result.

## Three-minute script

| Time      | Action                                                        | What to say                                                                                                                                             |
| --------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:25 | Open Landing and point out the Playground and Research links. | “Arbora makes a small compiler frontend inspectable and separates generated suggestions from deterministic verification.”                               |
| 0:25–0:55 | Open Playground and select a sample program.                  | “The lexer produces positioned tokens; the parser builds the reference AST and diagnostics locally.”                                                    |
| 0:55–1:25 | Open AST Visual, then Outline or JSON; select a node.         | “The AST is navigable and connected to source locations. The parser, not the model, remains the structural reference.”                                  |
| 1:25–2:10 | Inject a syntax error, choose an engine, and run repair.      | “The engine proposes candidates. The Verified badge only means the local parser returns zero syntax errors.”                                            |
| 2:10–2:35 | Compare Verified, Matches original, and Same AST separately.  | “Ground-truth correctness is a different question. For an injected error we know the original, so we can compare exactly.”                              |
| 2:35–3:00 | Open Research or Benchmarks and show the dataset/denominator. | “These committed numbers are baseline measurements. Neural metrics are not shown as completed because no trained-model evaluation artifact exists yet.” |

### Cold model fallback

If a model is cold, show the explicit “Model waking up, retry in 20 s” state. Retry only if time allows; otherwise switch to Classical and say that the displayed output came from the classical engine. Never imply that a fallback was generated by the selected model.

## 60-second elevator pitch

“Arbora is an educational MiniC compiler playground. It turns source into tokens, diagnostics, and an interactive AST, then lets classical or AI-backed engines propose repairs. The important design choice is that AI never gets to certify its own output: the deterministic parser checks every repair, and the interface separates ‘parses’ from ‘matches the original.’ The repo also includes seeded repair baselines, a data-leak check, and test workflows. The current measured artifacts are explicitly labeled baseline results; neural model accuracy is not claimed until a trained model has been evaluated.”

## Model warm-up checklist

- [ ] Confirm the Hugging Face Space is configured with the intended repair and AST repositories and a pinned revision.
- [ ] Check `GET /health` and confirm it reports ready model IDs/revision.
- [ ] Send one non-sensitive smoke request to `/repair` and one to `/ast`; do not use confidential source.
- [ ] Confirm Supabase `ARBORA_MODEL_URL` points to the Space and redeploy the gateway after secret changes.
- [ ] In Playground, select Arbora-T5 and verify the engine chip and local Verified badge behavior.
- [ ] If any step fails, use Classical and disclose that the remote model is unavailable.
